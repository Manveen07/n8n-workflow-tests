n8n-workflow-tests  ·  a stand-in for a private task tracker

One Slack button, tested before it reaches n8n

A toy n8n workflow: approve or reject a request from a Slack button. 45 tests run with plain Node, no n8n server and no packages to install.

Slack click→Ack→Raw body→Sign→Verify+route→Valid?→Save event→Build reply→Update cardred outline: a Code node, its JavaScript kept in logic/
1

The Code nodes run in Node

The JavaScript lives in logic/. Tests run the exact text the workflow file gives n8n.

  • A good Slack signature passes; a wrong, missing or old one is refused
  • Each button maps to one outcome
  • Clicks from anyone else are dropped
15tests
2

The workflow file is checked

The JSON is tested as committed, before any deploy.

  • Node order, node types, Slack answered first
  • Credentials by name; secrets only as placeholders
  • Each Code node equals a fresh build from logic/
12tests
3

A signed click is replayed

A script signs a recorded click the way Slack does and posts it to the webhook.

  • Pass: 200 in under a second and exactly one new event
  • The same click with a wrong secret writes nothing
  • A 200 that saved nothing is a failure
8tests
4

Deploys run from a script

One command creates or updates the workflow through the n8n API.

  • A second run updates by name: no "(copy)"
  • Values come from .env and are never printed
  • An error that echoes a key is shown without it
